# ADR 0010: 中核の共有モデルと規則の所有者

状態: 採用。対応: T2、D8。

## 問題

定義の読み込みと状態が定義型を共有すると、同じ第 2 層の `rpg → data` が生じがちです。迷宮の移動と場所の到着処理も、責務を分けなければ規則層の相互参照や共有 callback を必要とします。公開パッケージ間の横依存を許す方法は採りません。

## 決定と代案

定義型・その検証・YAML デコードを `internal/layer2/gamedata` が所有します。`data` はゲーム作者向けの型エイリアスと `Load(fsys, path)`・`Validate` を公開します。`rpg` は共有モデルを使います。共通型を別の公開パッケージに増やす代案は、利用者が覚える入口と公開面を増やすため採りません。状態のためだけに巨大な DB interface を作る案も採りません。

第 2 層の共有モデルには YAML ライブラリが必要です。従来 `data` に割り当てたデコーダの責務を共有モデルへ移すため、同じ外部依存を `private2` に割り当てます。層間の例外は追加しません。素材の YAML 設定・参照収集も `internal/layer2/assetpolicy` に置き、基礎層の `assetfs` は正規化済み承認と FS の操作だけを受け持ちます。

迷宮の生成・移動は `internal/layer3/dungeon`、共有する場所の規則は `internal/layer3/field` が所有します。公開 `world` が到着処理を組み立て、`init` による関数登録は使いません。迷宮の公開パッケージは追加しません。生成地図は DB 内の可変データなので、一つの実行が DB を専有します。プロセス共有の生成キャッシュは除去します。

イベントの即時効果は sealed な `Effect` の値を `Host.Handle(Effect)` で通知します。待機が必要な会話・選択・戦闘は `Request` として返します。多数の画面用メソッドを実装させる代案を避けます。任意の会話挿入抑制は別の 1 メソッドの契約です。

## 公開契約と検査

YAML の型エイリアスは公開契約です。内部に宣言を移して一覧から隠すことのないよう、API 検査は参照されたローカルエイリアスのフィールド・メソッドまで辿ります。生成された YAML 項目一覧とスキーマは `docs/schema.md`、`data/schema/` に置きます。パーサの補助関数・式の文脈表・素材の制作記録デコーダは公開しません。

メモリ上の保存 JSON は `rpg.Parse`、FS のバイト読み込みは `savefile.Load(fsys, path)`、保存先準備は `savefile.Prepare(id, Config)` とします。旧形式 JSON の受け入れは明示設定だけです。他のアプリケーションの保存ディレクトリは探索・移行しません。

依存方向は既存の `go-arch-lint`、公開面は `api/public.txt`、動作は中立なゲームの契約テストで検査します。実行方法は [開発と検証](../development/testing.md) を参照してください。
