# ADR 0017: 開発用のバランス表示と勝率計算の共有

状態: 採用。日付: 2026-10-19。[ADR 0012](0012-cli-ownership-and-output.md) の「戦闘曲線と設計評価は CLI だけが使うため CLI の internal に置く」を、勝率の計算について変更します。

## 利用者と問題

利用者は Gozen でゲームを作る作者と、作者の代わりに YAML を書く AI です。定義を直し、`--dev` で遊び、F9 でメモを残し、F5 で読み直す流れの中で、敵の強さの調整は `gozen sim`・`gozen curve` の文字の出力を別の端末で見る必要がありました。今いる場所の敵に今の一行がどれだけ勝てるか、Lv がいくつになれば勝てるかを、遊んでいる画面の上で確かめ、YAML を直したらすぐ数字が変わる形にしたい、という要望です。

画面と CLI で数字が違うと、どちらを信じればよいか分からなくなります。同じ関数と同じ乱数の種で数える必要があります。しかし勝率の計算は `cmd/gozen/internal/balance` にあり、`internal/play` から使えませんでした。`gozen sim` の 1 戦のループは `cmd/gozen/sim.go` に直接書かれていました。

## 決定

- `cmd/gozen/internal/balance` を `internal/headless/balance` に移します。`headless` component（第 4 層）が所有し、`cmd/gozen`（`sim`・`curve`・`design`）と `internal/play`（第 5 層）が同じ実装を使います。新しい公開 API は増やしません。`api/public.txt` も変わりません。
- `gozen sim` の 1 戦を `balance.Try`、集計を `balance.Odds.Add`、始まりの状態を `balance.Start`（新しいゲームは `FreshStart`、保存データは `SavedStart`）に分けます。i 戦目の乱数は従来どおり `PCG(seed, i)` です。共有化の前の出力と同じであることを単体テストで確かめます。
- `gozen sim` に `--state <file>`（F9 のメモの `.save` など。全員を全回復して始める）と `--hp`（勝った後の残り HP の 10%・50%・90% 点）を足します。既定の出力は変えません。
- 2026-10-19 追記（作者「HP 減った時の条件も知りたい」）: `--as-is`（`--state` の HP・MP・状態のまま始める）と `--streak N`（回復せずに続けて戦い、勝てた数。戦闘の間は `battle.End` で一行に戻す）を足します。共有の実装は `balance.Prep.AsIs`・`StreakOne`・`Streak`・`Percentile` です。
- `--dev` の F7 でバランス表示を出し入れします。今いる場所で出会う敵の群れ（遭遇の重み付き、場所の行動の `battle`、戦闘中の群れ）ごとに、今の一行を全回復した状態から `-n 200 --seed 1 --turns 60` 相当で勝率・残り HP の帯・平均ターンを数え、今の Lv から 5 Lv 上までの勝率（全回復）を線で描きます。誰かの HP・MP が減っているか状態異常があるときは、今のまま戦った勝率と残り HP を下の段に並べます。今の HP から回復せずに何連勝できるかの中央値（上限 9）も出します。
- 計算は `Update` の中で 1 フレーム 3ms までに分けます。ゲームの DB・状態は goroutine 間で共有しません（`data.DB` は迷宮の生成で書き換わり、並行利用を約束していないため）。状態は保存データを複製して使い、ゲームの乱数と状態を変えません。DB の差し替え（ホットリロード）、場所、一行の Lv・装備・スキルの木の変化で全部を測り直します。HP・MP・状態・経験値の変化では、45 tick 変わらなくなってから（戦闘中は待つ）今の HP の分だけを測り直し、回復や連戦のたびに 200 戦を回し直さないようにします。

## 代案

1. 別の goroutine で計算する案。フレームの時間を使いませんが、DB を読み直しの間も含めて共有するため、複製か排他が必要になります。DB の深い複製は大きく、排他はゲームの更新を止めます。開発時だけの表示に見合わないため採りません。
2. 画面からサブプロセスで `gozen sim` を呼ぶ案。数字は確実に一致しますが、ゲームの入口が CLI の存在と場所に依存し、埋め込みの FS や読み直し前のデータを渡せません。
3. 公開パッケージ（`x/balance` など）に出す案。ゲーム側からの用途がまだなく、公開の判断（[API の規約](../architecture/api-guidelines.md)）を満たしません。必要になったら別の ADR で判断します。

## 影響

- `headless` component の internal に、CLI と画面が共有する計算が置かれます。依存検査の設定は変えません。
- 計算中のフレームは最大 3ms 長くなります。表示を閉じている間は計算しません。
- サンプルの Wayfinder に強さの違う群れを 2 つ足し、Walker の能力を Lv の式にしました（Lv1 の値は従来と同じ）。
