# ADR 0001: モジュールと配置

状態: 一部変更。日付: 2026-10-18。対応: D1、D9、D10。別モジュールに分ける当初の決定は [ADR 0009](0009-single-module.md) で置き換えました。CLI の配置は [ADR 0016](0016-single-cli.md) で変わりました。Go の下限は標準ライブラリの脆弱性の修正を含む 1.26.9 に上げました（`go.mod`）。

## 背景

ゲームの中核を複数のゲームから使えるライブラリにします。制作支援の推論ランタイムを、ゲームを組み込むすべての利用者に要求する必要はありません。

## 決定

モジュールは `github.com/nao1215/gozen` の 1 つ、Go 1.26.4 を下限とする 1.26 系で始めます。CI は厳密な下限と stable を検査します。依存は Ebitengine v2.10.4、goccy/go-yaml v1.19.2、x/image v0.45.0 を採用します（`go.mod:1`）。

ライブラリは `engine/` を挟まずモジュール直下に置き、実装は `internal/` に隠します。CLI は `cmd/gozen` の 1 本に置きます（[ADR 0016](0016-single-cli.md) で 4 本から変更）。制作支援の実装は `internal/promptgen`・`internal/mosaic` とその配下に置き、公開 API にしません。入れ子のモジュールも `go.work` も作りません。

## 理由

短い import パスで公開境界を示します。Go は使用しないパッケージの依存をビルドしないため、制作支援の cgo・ONNX をライブラリ利用者に要求せず、単一モジュールを維持できます。CLI は用途ごとに独立した名前と help を持ち、必要な機能だけを導入できる形にします。

## 結果

ルートの `go test ./...`・lint・build が全体の入口です。推論の実行検査は前提条件を持つ別の対象に分けます。モデルは同梱しません。内容の境界は [ADR 0004](0004-content-boundary.md) に従います。
