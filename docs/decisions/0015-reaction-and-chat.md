# ADR 0015: 人物の反応とチャット

状態: 採用（2026-10-19）。置き場所: `react`（第 3 層の規則）・`chat`（第 1 層の基礎）。

## 利用者と問題

ゲーム作者が、プレイヤーの言葉や行動に対して人物が反応する遊びを作れるようにする。想定する利用者は 3 つ。

| 利用者 | 刺激 | 反応 |
| --- | --- | --- |
| 配信者のゲーム | 自由入力のコメント、投げ銭の額、流れるボットのコメント | 拾う・無視・反応の台詞と表情・好感度 |
| オープンワールドの住人 | 出来事（盗んだ、装備、久しぶりの来訪）と話しかけ | 台詞・態度・噂 |
| ネット対戦 | 相手の言葉 | 表示の前の伏せ字、ボットの相槌 |

LLM は使わない（配布物だけで完結させ、通信費と予測できない出力を避ける）。判定の精度は低くてよい。精度の代わりに、人物の立ち回りで賢く見せる。

1. **確信が低いときは人物が主導権を取る。** 煽る・聞き返す・話題を変える。外しても性格として成立する。
2. **覚えて、後で持ち出す。** 以前の話題や出来事を台詞に差し込む。
3. **答えを狭める質問をする。** 問いを出した直後は、期待する答えを優先して照合する。
4. **同じ反応を繰り返さない。** 台詞の連続、同じ言葉の連投を検出して反応を変える。

## 決定

反応（判定）とチャット（流れ）を独立した 2 パッケージにする。互いに import しない。つなぐのはゲーム側。

### react: 刺激 → 解析 → 規則 → 反応

```
Stimulus（言葉・出来事・数値） → Analyzer（コード） → Tag と確信度
                                                       ↓
                       Memory（人物ごと） → Rule（YAML、条件は expr） → Reaction
```

| 型・関数 | 誰が何のために使うか |
| --- | --- |
| `Stimulus{Kind, From, Text, Values, Tags}` | ゲームが刺激を渡す。`Kind` は `say`（`KindSay`）や `event.steal` のような文字列。言葉が無い出来事は `Tags` に既知の印を入れる |
| `Analyzer` interface（1 メソッド: `Analyze(Stimulus, *Mind) []Tag`） | ゲームが独自の判定を足す。`Mind` の `Recall`・`Mood` を読める |
| `Tag{Name, Score, Slot}` | 解析の結果。`Score` は 0〜1 の確信度、`Slot` は当たった辞書の語（記憶や台詞に差し込む） |
| `Load(fsys, path)`・`Parse(b)` → `(*Book, error)`、`(*Book).Validate` | 辞書と人物の YAML を読み、参照を検証する |
| `New(book, id, cfg Config) (*Mind, error)` | 人物 1 人の実行状態を作る。乱数・時計・独自の解析器・入力の上限は `Config` で渡す |
| `(*Mind).React(Stimulus) (Reaction, error)` | 1 つの刺激に反応する。条件式の評価の失敗だけを error にする |
| `(*Mind).Ask(id) (Reaction, error)` | ゲームの都合で人物から問いを出す（話題を振る） |
| `Reaction{Rule, Lines, Face, Delta, Mood, Confidence, Tags, Ask}` | 画面が台詞・表情を出し、ゲームが機嫌などに使う |
| `(*Mind).Mood`・`Recall`・`Save`・`Restore` | 機嫌と記憶を読み、保存・復元する（JSON のバイト列） |
| `(*Mind).NewSession` | 次の配信・次の来訪など、同じ人物との新しい会話を始める。連投を見る直近の言葉と答え待ちの問いを忘れ、機嫌・記憶・冷却は残す（2026-10-19、配信者のゲームが配信をまたぐために追加） |
| `Normalize(s)` | 辞書と同じ正規化を、ゲームの独自の解析器で使う |

標準の解析器（辞書の外の処理だけをコードに置く）:

- **正規化:** 全角半角、カタカナをひらがなに、英字を小文字に、空白・句読点・伸ばし棒を除き、3 回以上の同じ文字を 2 回にする。形態素解析は使わない（WASM の大きさを抑え、部分一致で足りる）。
- **辞書:** 語の一覧を部分一致で引き、タグを付ける。語ごとに任意の重み（確信度）を付けられる。
- **縦読み:** 2 行以上のとき、各行の頭の文字をつないで辞書を引き、`acrostic_<タグ>` を付ける。
- **連投:** 同じ送り手の直近の言葉と同じなら `repeat`（条件では回数を `repeats`）。
- **記憶への言及:** 覚えた文字列（2 文字以上か漢字 1 文字）に触れていれば `recall`。
- **空の発言:** `say` で言葉が無ければ `empty`。
- **数値:** 投げ銭の額などは `value.NAME` で条件から直接読む。

条件式（`expr`）で使える名前: `tag.T`（確信度、無ければ 0）、`slot.T`、`mem.K`（無ければ 0）、`value.N`、`mood`、`turn`、`kind`、`from`、`length`、`asked`、`answer`、`repeats`、`confidence`。台詞では `{from}`・`{mood}`・`{slot.T}`・`{mem.K}` を差し込める。検証は未知の名前・タグ・表情・問い・差し込みを誤りにする。

人物の YAML（`react/react_test.go` の例を縮めた物）:

```yaml
lexicon:
  cat: [ねこ, 猫, {にゃ: 0.4}]
  dog: [いぬ, 犬]
  rude: [ばか, アホ]
tags: [gift]            # ゲームが Stimulus.Tags で付けるタグ
people:
  - id: host
    mood: 50
    faces: [normal, smile, angry, think]
    likes: {cat: 10, rude: -20}
    asks:
      - id: pet
        say: [犬派？ 猫派？]
        expect: [cat, dog]
    rules:
      - id: answer_cat
        when: asked == "pet" && answer == "cat"
        say: [わかってるじゃん]
        remember: [{key: pet, set: "{slot.cat}"}]
      - id: gift
        kind: event
        when: tag.gift > 0 && value.amount >= 1000
        say: ["{from}、ありがと！"]
        delta: 15
      - id: callback
        when: tag.recall > 0
        say: ["{mem.pet}の話、覚えてるよ"]
      - id: cat
        when: tag.cat >= 0.5
        say: [猫いいよね]
        remember: [{key: cats, add: 1, turns: 3}]
        ask: pet
        cooldown: 2
    dodge:
      repeat: [それさっきも言った]
      unsure: [ふーん。で？]
      unknown: [日本語でおｋ]
```

規則は上から評価し、`kind` と冷却が合い、条件が成り立つ最初の規則を採る。どれも成り立たなければ、`repeat`（連投）、`unsure`（何かのタグがある）、`unknown`（何も無い）の順で `dodge` の束から選ぶ。台詞は直前と同じ物を避けて選ぶ。機嫌は `likes` × 確信度の和と規則の `delta` で動き、`mood_min`〜`mood_max`（既定 0〜100）に収める。問いを出すと、次の刺激（`turns` 回）で `expect` のタグが確信度 1 になり、`asked`・`answer` で読める。

### chat: 流れるメッセージ

| 型・関数 | 誰が何のために使うか |
| --- | --- |
| `Message{ID, From, Text, At, Values}` | 1 件のメッセージ |
| `New(cfg Config) *Log`、`Post`・`Pull`・`Recent`・`Since` | 上限付きで直近を保持し、画面が流す・拾う。長い言葉は切る |
| `Source` interface（1 メソッド: `Poll(now time.Duration) []Message`） | プレイヤーの入力、ボット、ネット対戦の相手を同じ形で流す |
| `Filter` interface（1 メソッド）、`NewMask(words) *Mask` | 表示の前に伏せ字にする・捨てる。`Mask` は全角半角・かな・大小・空白・記号・伸ばし棒を無視して照合し、元の文字を `*` にする。人どうしの言葉は必ず通す |
| `Load`・`Parse` → `(*Script, error)`、`NewCrowd(script, CrowdConfig) *Crowd` | ボットの台本（名前、毎秒の平均の数、気分ごとの台詞）。`Mood` で気分を変え、`Burst` で出来事への一斉の反応を出す。長い中断の後も 1 回で 20 件までしか出さない |

ネット対戦の通信は実装しない。`Source` の差し込み口だけを用意し、WebRTC や中継サーバーは利用者が決める。

### 層

`react` は第 3 層の規則に置き、`expr`・YAML・`golang.org/x/text/width` だけを使う。Ebitengine を使わず、描画なしでテストする。`chat` は第 1 層の基礎に置き、標準ライブラリ・YAML（ボットの台本）・`golang.org/x/text/width` だけを使う。同じ段の横依存の禁止に従い、両者は互いに import しない。表示は利用側が組み立てる。

## 代案

- **LLM（外部 API・ブラウザ内の小型モデル）:** 通信費、配布の大きさ、出力の制御の難しさで採らない。
- **形態素解析（kagome など）:** 辞書で数十 MB 増え、WASM に向かない。部分一致で足りるかを試作で確かめる。
- **`x/` の実験として置き、使い手が 2 つになってから昇格する:** Gozen は公開前で外部の利用者がいないため、公開の層に置いても API の変更の費用は小さい。代わりに下の「公開前の見直し」で確かめる（2026-10-19 作者の判断）。
- **反応とチャットを 1 つにする:** オープンワールドはチャットを使わず、ネット対戦は反応を使わないので分ける。

## 検証

- `react/react_test.go`: 会話の列と、期待する規則・台詞・機嫌の表（乱数の種を固定）。問いと記憶の持ち出し、冷却、記憶の期限（回数・時間）、保存と復元、正規化、検証の誤り 13 種。`FuzzReact` は長い・壊れた入力で機嫌と確信度が範囲に収まることを確かめる。
- `chat/chat_test.go`: 上限と ID、切り詰め、捨てる Filter と伏せ字の表記揺れ、ボットの頻度・気分・一斉・中断後の上限、台本の検証。`FuzzMask` は伏せ字が文字数を変えないことを確かめる。
- 未対応: 半角カナの濁点（ﾊﾞ）は伏せ字の照合で 1 文字にまとめない。作者向けに人物と対話して採った規則を確かめる CLI（`gozen talk`）は後で検討する。

## 決まったこと（2026-10-19 作者の回答）

- **好感度・機嫌は人物（`Mind`）が持つ。** 規則の条件（`mood`）と台詞から直接使え、記憶と一緒に保存する。ゲームは `Reaction.Delta` と `Mind` の値を読む。
- **記憶の期限は、記憶ごとに「会話の回数」か「ゲーム内の時間」を選べる。** 時間はゲームが `Config` の時計で渡す。省略時は忘れない。
- **辞書の語に任意で重みを付けられる。** 省略時は 1。タグの確信度は、当たった語の重みを使う（例: `{ねこ: 1, にゃ: 0.4}`）。

## Gozen の公開前の見直し

Gozen を公開する前に、次を確かめる。満たさない物は API を直すか、公開から外す。

1. **性質の違う利用者が 2 つ、実際に使っている。** 配信者のゲームと、2 つ目（例: RPG の町の住人、またはサンプル）。片方の都合だけの API を残さない。
2. **YAML の書き方が `docs/schema.md` に載り、`Load` の検証と `gozen check` が誤りを見つける。**
3. **信用できない入力に耐える。** 自由入力・ネット対戦の言葉を受けるので、正規化・解析器・伏せ字に fuzz テストがあり、大きな入力で時間と記憶が抑えられている。
4. **WASM で動くことを、利用者のゲームで確かめた。**
