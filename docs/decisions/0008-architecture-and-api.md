# ADR 0008: 下向きの依存と小さな API

状態: 採用。日付: 2026-10-18。対応: D8。

## 背景

画面を使わない中核の再利用と、理解できる大きさの公開 API を維持します。パッケージの相互参照や過剰な公開は、描画なしでの利用や互換維持を難しくします。

## 決定

依存は基礎 → モデル → 規則 → 進行 → 表示 → 入口の順に積み上げ、上位から下位への参照だけを許可します。同段の別の公開パッケージへの横依存、逆依存、安定パッケージから `x/` への依存を禁止します。Ebitengine は表示と入口に限定します。

所有者を持つ internal はその所有層と同じ制約を受け、共有 internal は `internal/layerN/` として同層以上から利用できます。共有 internal 自身は下位だけに依存します。`savefile` は第 1 層、`dungeon` の規則は第 3 層としますが、後者を公開する約束は追加しません。

go-arch-lint v1.19.0 の版 3 設定でこの依存を表し、`make lint` と CI で実行します。T1 では空の予約 component を許しますが、未知のパッケージと vendor は許しません。テストは上位の組立てを行うため runtime の検査から外し、ライブラリからテスト補助への依存は許可しません。

API は実際の利用者に必要なものだけを公開します。小さな `Config`、統一した `Load(fsys fs.FS, path string) (T, error)`、1〜2 メソッドの拡張 interface を使い、命名・context・エラーを [API 規約](../architecture/api-guidelines.md) に揃えます。標準の go/ast による公開識別子の一覧を `api/public.txt` に保存し、テストで増減を検出します。

## 理由

描画依存と公開面の拡大を、レビューの注意だけに頼らず検出できます。過剰な interface と設定機構を作らず、利用者が覚える入口を揃えます。

## 結果

複数のパッケージで使う機能は、共有内部実装・小さな契約・上位の組立てに責務を分けます。例外を設定に追加して済ませません。必要な例外は代案と理由を ADR に記録してから判断します。識別子一覧はシグネチャ互換性の検査ではないため、godoc と契約テストも維持します。
