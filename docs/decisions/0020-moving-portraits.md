# ADR 0020: 動く立ち絵（puppet）

状態: 採用（2026-10-19）。置き場所: `puppet`（第 5 層の公開パッケージ）・`internal/layer5/puppet`（共有の実装）・`internal/layer2/puppetdef`（YAML の型と検証）・`gozen puppet`（検査と差分の切り出し）。

## 利用者と問題

一枚絵のキャラクターを、配信者のアバターのように動かしたい。作者の決定（2026-10-19）は「キャラを動かす。それなりのアニメーションで」「Gozen の汎用機能で」。

| 利用者 | 使い方 |
| --- | --- |
| 配信者のゲーム（最初の使い手） | 胸から上の配信者の透過 PNG を、背景と UI の間の層に常に出す。コメントへの反応で跳ねる・うなずく・表情を変える。台詞の間は口を動かす |
| RPG の会話の立ち絵（次の使い手） | 話している人物の立ち絵がまばたきし、台詞の表示中に口を動かす。会話の表情の指定で表情を替える |

手で描ける素材は「基準の絵」と「目を閉じた絵」「口の形の絵」「別の表情の絵」程度に限る。部品に分けた絵や、骨と重みの手作業（リグ）は求めない。

## 決定

一枚の基準の絵に、小さな差分の絵を重ね、その結果を網目（三角形の格子）で歪ませて描く。

1. **合成:** 毎フレーム（変化があったときだけ）、基準の絵・表情の差分・閉じた目・口の形を、基準の絵と同じ大きさの画像に重ねる。表情の切り替えは前後の差分を透明度で混ぜる。
2. **変形:** 合成した画像を、長辺 48 分割ほどの格子にして `DrawTriangles` で描く。頂点ごとに「頭の重み」と「髪の重み」を前もって計算しておく。頭の重みは頭の円の中で 1、円の外 0.35 半径で 0、首の付け根の手前 0.4 半径で 0 に落ちる。これで頭を首の付け根の周りに回し・ずらしても首がなめらかにつながる。髪は、頭の中心の動きを追うばね（硬さと減衰）の遅れの分だけ、髪の範囲（矩形か多角形、下ほど大きく動く）をずらす。呼吸は体全体を下端を基準に縦に伸縮し、反応は全体の平行移動・拡大縮小と頭の角度・ずれに足す。
3. **動き:** 待機の揺れは周期の違う正弦の和、首かしげは間隔に揺らぎのある出来事、まばたきは揺らぎのある間隔とたまの 2 回、口は話している間だけ 2〜3 種の形を不規則に替える。乱数は `Config.Rand`（nil は固定の種）で、同じ種・同じ回数の Update なら同じ動きになる。

| 型・関数 | 誰が何に使うか |
| --- | --- |
| `Load(fsys, path) (*Rig, error)` | YAML と PNG を読み、検証する。全体の大きさの差分の絵は、違う所だけを縁をぼかして切り出す（`area` で探す範囲を絞れる）。透明の無い差分の絵は下の絵の透明を使う |
| `(*Rig).Size()` | 配置の計算に基準の絵の大きさを使う |
| `Config{Rand, TPS, Face}`、`New(rig, cfg) (*Puppet, error)` | 画面に出す 1 体を作る。同じ Rig から何体でも作れる |
| `Update`・`Draw(dst, op)` | ホストの Update・Draw から呼ぶ。`op` の GeoM・ColorScale・Blend を使い、補間は常に線形 |
| `Speak`・`Stop` | 台詞の表示中だけ口を動かす |
| `React(name)` | 跳ねる（hop）・縮む（shrink）・揺れる（shake）・うなずく（nod）・かしげる（tilt）、または YAML で名前を付けた強さ違いを一回鳴らす |
| `SetFace(name)` | 表情をふわっと替える（既定 0.25 秒） |
| `Close` | GPU の画像を解放する |

RPG の会話では、仲間の定義 `Actor.Puppet`（`data` の公開フィールド 1 つ）に puppet の YAML を書くと、会話の窓の立ち絵が puppet になる（`internal/play/puppets.go`）。台詞の表情の名前で `SetFace` し、文字が出ている間だけ口を動かす。

`puppet` の公開は 17 宣言（型 3・関数 2・メソッド 8・フィールド 3・パッケージ）。合成・変形・動きは内部に置き、強さの値は YAML だけで変える。YAML の書き方は [動く立ち絵](../architecture/puppet.md) に書く。

### 層

`puppet` は Ebitengine を使うので第 5 層の公開パッケージとし、`.go-arch-lint.yml` に独立した component を足す（`gfx` などと同じ許可。横の `gfx`・`play` を参照しない）。実装は `internal/layer5/puppet` に置き、後で `internal/play` が会話の立ち絵に使うときも横依存にならないようにする。YAML の型と構造の検証は画像を知らないので `internal/layer2/puppetdef`（第 2 層、YAML の利用が許されている）に置く。第 5 層の共有の実装に YAML を許す例外は足さない。

`gozen puppet` は同じ `Load` で検査し、各差分の位置を表示する。`--out` で差分を小さく切り出した絵と `at` 付きの YAML を新しいディレクトリに書く（配布物を小さくする）。

## 代案

- **Live2D:** 動きの質は高いが、Go の実行環境が無く（公式 SDK は C++・C#・JS・Java）、cgo と再配布の規約を持ち込む。素材も部品分けとリグの手作業が要り、「一枚絵と差分」で済ませる目的に合わない。
- **Inochi2D:** 自由な規約の部品式。D 言語の実行環境で、Go から使うには移植か cgo が要る。素材も部品分けとリグが要る点は Live2D と同じ。
- **絵を部品（層）に細かく分ける方式:** 髪・顔・体を別の透過 PNG にして重ねて動かす。動きの自由度は上がるが、生成した一枚絵から部品を切り出し、隠れていた所を描き足す手間が大きい。網目の変形なら一枚のまま頭と髪を動かせる。部品が欲しくなったら、同じ網目に部品ごとの重みを足す形で後から広げられる。
- **差分なしで変形だけ:** 目と口は変形で作れない（閉じた目は別の絵が要る）。差分は小さい絵で済む。
- **`gfx` に入れる:** `gfx.Load` がフォントの名前を使っており、`Load(fsys, path)` の規約と衝突する。用途も別なので独立したパッケージにした。

## 検証

- `internal/layer2/puppetdef/spec_test.go`: 正しい YAML の読み込み、誤り 26 種（未知のキー、絵の拡張子、範囲、強さ、反応の種類、髪だけで頭が無い など）、`FuzzParse`。
- `internal/layer5/puppet/puppet_test.go`: 差分の自動の切り出し（場所、縁の透明、小さな点の無視、違いが無い絵）、読み込みの誤り 8 種、同じ種で同じ動き・違う種で違う動き、まばたきの回数と口の形、表情の混ざり、反応が終わると元に戻ること、網目の元の座標が絵の中にあることと 3000 回の更新で頂点が絵から頭の半径以上離れないこと、頭の重み（首の付け根より下は動かない）、`--out` の書き出しを読み直して同じ差分になること。
- `puppet/puppet_test.go`: 公開 API の読み込み・作成・反応・表情・誤り。`puppet/graphics_test.go`（`make graphics`、Xvfb）: 実際の描画を読み、基準の色・半透明・まばたき・口・表情の途中の色と最後の色・跳ねて下端が浮くこと・Close 後に描かないこと・網目が図形の外に描かないことを確かめる。
- `internal/layer2/gamedata/check_test.go`: 仲間の `puppet` の誤り 4 種（ファイルが無い、YAML の誤り、絵が無い、仲間の表情が無い）と正しい書き方。
- `e2e/atago/puppet.atago.yaml`: `gozen puppet` の表示、`--out` の書き出しと読み直し、既存の出力先、誤りの終了コード。
- 未確認: WASM・Windows・macOS での描画。大きな絵（長辺 4000 画素以上）を何体も出したときの速さ。

## Gozen の公開前の見直し

1. 配信者のゲームと RPG の会話の 2 つが実際に使っている。片方の都合だけの API（たとえば `Config.Face`）を残さない。
2. 動きの強さの既定値が、大きさの違う絵（胸から上の大きな絵と、会話の全身の立ち絵）で両方自然に見える。
3. 部品式の要望が出たら、網目の重みを部品ごとに持つ形で広げられるかを確かめる。
