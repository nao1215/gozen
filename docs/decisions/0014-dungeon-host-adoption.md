# ADR 0014: 独自の迷宮操作を組み立てる公開面

状態: 採用。対応: SW2、D7、D8。

## 利用者と問題

ゲーム側の探索コントローラと経路評価は、一歩ずつ進めて条件付きの地形、移動敵、一回限りの操作、訪問記録を観測する。`headless.Driver.Walk` は目印までを一括実行するため、途中の判断をゲーム側で行えない。内部実装を複製すると、画面とゲーム側の経路判定が別の規則になる。

## 決定

`dungeon` を第3層の公開入口に追加する。実装の所有者は `internal/layer3/dungeon` のままとし、公開面はゲーム側の操作に必要な次の組に限る。生成アルゴリズム、描画、探索用の内部キャッシュは公開しない。既存の層の許可内で実装し、例外は足さない。

| 公開識別子 | 誰が何のために使うか |
| --- | --- |
| `Cell`、その `X`・`Y`・`Char`・`Tile`・`Look`・`Solid`・`Passable` | 独自の探索コントローラが現在の位置、条件付きの地形、操作対象、通行可否を判断する |
| `Of`・`CellAt`・`Front` | 地図を使うホストが現在の階とマスを観測する |
| `Dive`・`Place`・`Turn`・`Forward`・`Look` | ゲーム側が階への配置と一歩単位の操作を実行する |
| `Next` | 自動探索するホストが次の一操作を選び、各操作の間に独自の判断をする |
| `Seen`・`Shown`・`Spent`・`Completed` | 探索方針が訪問済み・表示済み・操作済み・階の完了を区別する |
| `Walked`・`Hunters` | 操作を組み立てるホストが全域到達と条件付き移動敵の更新を進める |
| `Trigger`・`Slides`・`SlideEnd` | 経路評価が操作方法と移送後の位置・向きを判定する |
| `BattleMusic` | ゲーム側の回帰検査が、階と敵グループから実際に選ばれる戦闘曲を確かめる |

`DB`・`State`・定義は呼出側が所有する。借用した定義は変更せず、同一状態を並行操作しない。命令を返す操作は、呼出側が `event` または `headless` でその命令を一度実行する。`Next` の戻り値は `here`・`left`・`right`・`look`・`forward` で、内部の方向定数は公開しない。

戦闘曲の優先順位は、定義ファイルだけの検査では実際の選曲と一致することを確かめられず、既存の公開入口からも画面なしで観測できない。この乗り換えでは `BattleMusic` の選曲結果だけを公開し、音声バックエンドや表示内部の設定は公開しない。

## 採らない案

体験版の内部構造と制作支援の型は公開しない。ゲーム側は `gozen trial` の生成物と一覧、`gozen prompt --format json` の出力を検査する。作品ごとの自動プレイ評価は、公開された状態・戦闘・イベント・迷宮を使ってゲーム側に置く。評価用 callback や私的な評価基準をライブラリへ追加しない。

多数の構図を検査する利用者には `gozen prompt --scenes FILE --format json` を用意する。構図ごとに設定を再解析する費用を避け、カタログの内部型を公開せず一括出力を提供する。作品独自の必須語は利用側のカタログに置く。

## 検証

公開面は `dungeon/dungeon.go:1`、利用契約の検査は `dungeon/dungeon_test.go:1`、識別子一覧は `api/public.txt`。内部の迷宮テストと公開入口からの移動・保存復元・イベント実行を照合する。移植元での検証結果と非公開の資料は公開リポジトリへ入れない。
