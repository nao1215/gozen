# Changelog

Changes not yet released are tracked under Unreleased. All packages and the gozen command share one module version. The v0 API is being established; experimental packages, when there are any, live under `x/` and carry no compatibility promise.

## Unreleased

### Added

- Run a game directory with `gozen play run <game-dir>` without writing a Go wrapper. The CLI and `play.Main` share standard options, development tools, rendering and save behavior.

## v0.6.0 - 2026-10-24

Continuous stairs through bounded stacked spaces, safer limits for oversized game data and pictures, and faster documentation CI. Existing single-floor dungeons keep their renderer and transitions; stacked spaces opt in with schema version 8.

### Fixed

- Prevent map route distance overflow and avoid building paths for destinations that are not offered as choices. Map refresh and battle mouse targeting also reuse existing layout information.
- Bound picture reads and decoded dimensions before allocation, sharing checks between ordinary pictures and puppets. Reject roads above 10,000 steps and troops above 32 enemies; pictures are limited to 8,192 pixels per side, 16,777,216 pixels and 64 MiB of encoded data.
- Correct documentation command lists and verification steps, and clarify the limits of trial pruning and automated balance advice.

### Changed

- Wait for balance measurements to finish in capture scripts and graphics E2E checks instead of sleeping for 5,200 frames; invalid panels and measurement errors fail the capture.
- Split documentation image verification across four capture-aware CI shards, build only the selected samples, and log phase durations while preserving complete image comparison coverage.

- Cancel superseded pull-request benchmarks and refresh job-specific CI caches per revision while restoring compatible dependency caches.

### Added

- Opt-in bounded stacked spaces (schema version 8): continuous bidirectional stairs, open-air levels, solid floor slabs, textured materials and a sky panorama. Existing dungeons retain their renderer and transitions. Includes the Terrace Quarter demo, save/restore and movement regression tests, and graphics E2E checks.

- CLI E2E scenarios for excessive road steps, enemy counts and image dimensions, including successful checks after repairing each input, plus regression tests and large-map benchmarks.

## v0.5.0 - 2026-10-22

A relationship chart in the character book, a calmer breeding lead-in and softer battle motion, one size for screen captures, and safer handling of sizes taken from YAML.

### Added

- The character book has a Tab relationship chart with face icons, lines coloured by kind (family, friend, like, love, rival or enemy, other), one-way arrows, a legend, the player as a node, affiliation grouping, lines routed around unrelated faces, camera follow and wheel zoom. Choosing a character focuses the chart on it and the people related to it, arranged in a circle around it. Profiles accept `affiliation` and relations accept `kind`; `gozen check` validates kinds and targets (ADR 0038). Go Zen has eight profiles.
- Puppets accept `motion.hit: soft_only`: a hit leaves the head and body still and only the `soft_sway` regions answer to damage. Go Zen's Succubus uses it.

### Changed

- The birth's lead-in, before the parents' lights meet, is about 1.5 times longer.
- Every screen capture in the README and on the site is 720x405, so captures shown side by side line up.
- Go Zen's Succubus sways more gently.

### Fixed

- Sizes read from YAML or computed from it (dungeon generation, paths, pages, campaigns, plans and events) are bounded before allocation, multiplications are guarded against overflow, and values written into messages are quoted with `strconv.Quote` (CodeQL alerts).

## v0.4.0 - 2026-10-22

Monster collection and livelier battles: schema version 6 adds a monster book, capture after battle, a ranch and breeding in the manner of Dragon Quest Monsters (sexes, family trees, a staged birth at Yorn's altar), and battles gain transforming and merging foes, pictures by HP and moving monsters. `gozen sim routes`, `gozen sim breed` and `gozen sim campaign --compare` measure the new parts, and the browser samples load their files on demand.

### Added

- Battle puppets now support a shared `soft_sway` YAML list with rectangle or ellipse regions for actors and enemies. Go Zen's Succubus blinks, moves its mouth while acting, and sways softly; Drip Slimes merge into the author-generated King Slime. Four battle feature captures are registered for the README, site, and cookbook.
- Monster instances now have saved male/female sexes, species sex restrictions and optional male ratios. Breeding requires opposite-sex parents; ranch and party screens show signs, while `gozen check` and `gozen sim breed` account for sex-impossible rules and reachability.
- The monster book now offers a navigable, foldable family tree, and `gozen book` exports the same buildable routes as text or JSON. Go Zen adds Yorn's Breeding Altar and a two-generation route to Succubus through Whisper Imp and Vampire.

- Monster collecting (ADR 0036, schema version 6): post-victory recruitment with staged Yes/No, saved monster instances and a reserve, a ranch screen for swaps, release and breeding, inherited skills and plus growth, `bestiary.<id>.caught`, `gozen sim breed` (text and JSON), GZN0116 and GZN1112, and recruitment and recipes in `gozen book`. Go Zen now has 40 non-boss monster species assigned to nine families, 20 capturable species, seven specific recipes and nine family rules, with deeper species gated to later generated floors.
- Monster book: `enemies.<id>.lore`, `ui.bestiary`, staged discovery in saved state (`bestiary.<id>.seen` and `.defeated`), F4 in `--dev`, GZN0115 for troop enemies without lore, and pages in `gozen book` (ADR 0035).
- Go Zen adds 35 author-owned enemy pictures and definitions to B3 encounters, including rare mimic encounters; the sample enables the monster book.
- `gozen sim routes` explores event choices without a screen and reports reached clear/game-over outcomes, never-offered choice options, flags reported by GZN0112, and bounded exploration status; `--fail-unreachable` opts into a failing exit status.
- Four more dungeon themes in the `gozen` binary: `temple` (white stone with teal tiles), `sewer` (wet stone, grates and pipes), `forest` (walls of roots) and `tomb` (sandstone with carved signs). `gozen theme list` shows nine.
- Four dungeon themes from the author's own game: `keep` (gray stone with pillars), `dream` (purple walls of eyes), `mine` (timbered shafts) and `vine` (bricks hung with ivy). `gozen theme list` shows thirteen.
- `gozen sim campaign --compare strategies|tactics` plays every strategy or declared tactic on the same seed range and reports win rate, mean ending turns, mean player regions held, and per-region ownership changes, mean turn of the first ownership change, end holders and player win rate by held turn. `--format json` writes the same comparison report as JSON.

### Changed

- Browser samples no longer include the games' embedded files in their WebAssembly builds. They read a small manifest and fetch assets only when opened, while desktop builds keep embedding the game directory. The pages load precompressed `.wasm.gz` files and decompress them before instantiation; browser saves remain in `localStorage`.

## v0.3.0 - 2026-10-21

Campaigns join RPGs and novels: schema version 5 adds a war of regions over turns (ADR 0030), with a sortie screen and clashes of armies, beside the dungeons and towns of the same game. Dungeons gain themes: `theme: cave` and a few more fill a dungeon's pictures, and `gozen theme add` copies them into a game.

### Added

- A clash can show each unit as an army of the leader's kind: `clash.armies.<kind>` lists poses of one soldier (facing right; the foe side is turned), which the engine lines up in staggered rows, smaller and higher toward the back, the poses scattered, with the soldiers lost falling from the back rows, a gauge of the troops and their number under it. The kind follows the leader (`generals.<id>.army`, `enemies.<id>.army`: men, women, monsters), and `clash.layout` places the leaders: `below` (the default) puts the armies above and a large bust card of each leader along the bottom, with no rope and no HP bar; `front` stands a small card in front of each army. `gozen check` reports missing pictures and unknown kinds. Without armies the soldiers in ranks (`clash.soldiers`) remain.
- A clash shows a strike as a short burst of dust and sparks where the armies meet (no white line), and a soldier picture is drawn facing right, the engine turning the foe side to face left.
- Campaigns (ADR 0030, schema version 5): `regions` and `factions` in `data/` and `campaign` in `game.yaml` define a land of regions held by sides over turns, with the player's orders and generals. The state is in variables with generated names; the expression names `region`, `faction`, `campaign`, `generals`, `general`, `target` and `next_to` read it, and `set` writes a region's owner, troops and values and a general's troops. `gozen check` reports borders written on one side, unknown owners and capitals, a capital not held at the start, the orders' and the rules' words, and warns of regions in two parts and of a win or a defeat that holds at the start.
- The rules of a campaign (ADR 0030): the orders are listed in the campaign's place with "End turn"; the command `order` asks for the general and the target region (or takes them written), marches by the numbers of `clash`, and runs the order's `do` with `general` and `target` bound; `end_turn` lets the other factions draft and march by their `ai` rules and starts the next turn. A campaign ends once: `lose` or the end of the last turn runs `lost` and a game over, `win` runs `won` and clears the game. The new command `game_over` ends a game lost without a battle.
- A campaign's map (ADR 0030): the points named like regions stand flags in their owners' colours with the garrisons, a band tells the turn and the actions, the meters and a window of the region chosen show, the generals stand with their troops, and OK on a region lists its orders. Scripts take `order` and `end_turn`, and the trace writes `region`, `order` and `end_turn`. The clash reads the general's stats (`a.atk` and the rest): the generals are the game's actors, shared with its dungeons and battles.
- `gozen sim campaign` plays a campaign many times headless with a strategy for the player (`--as greedy|random|ai`, `-n`, `--seed`, `--format json`) and prints the win rate, the turns, the regions each faction held turn by turn, the factions that fell and when, and the orders given.
- An order with `fight: battle` decides its march by the game's battle: the general against the region's `defend` troop, the troops written back after it (a win keeps the share of the HP left), no game over on a loss. In battle, `self.troops` is a general's troops or the garrison of the region marched on.
- Campaigns in the manner of Kichikuou Rance: `calendar: week`, `count: orders` with `per_turn` on each order, marches open `until_taken`, `generals: N` marching together (the order asks who else goes), and `defeat: {out: N}` for a general beaten to no troops. `orders.<id>.open`, `campaign.week`, `campaign.year`, `campaign.taken` and `generals.<id>.out` read them.
- A clash shown as units (`fight: clash_view`): the generals against the region's `defend` troop, up to four units a side in front and behind, played by the rules round by round and shown as two armies on the terrain's picture (`terrain`, `clash.backgrounds`, `clash.soldiers`) with strikes, routs and a table of the losses. `on_win`, `on_lose` and `on_draw` run a general's word after a march. The soldiers in the ranks tell the troops (`clash.per_soldier`, `clash.rope`). With armies a unit shows few soldiers (`clash.max_soldiers`, 4 by default; one stands for the troops marched with divided by it unless `per_soldier` is set), and under `layout: below` a small face on each gauge and the cards under their armies tell whose is whose.
- A sortie screen for a march: who goes in the front and the back slots, each with a tactic. `clash.units` (1 to 4, 1 a duel), `clash.tactics` (how a unit picks the foe it strikes; the engine's front, weakest, strongest, leader and guard by default) and `clash.skills` (charged each round, used instead of a strike: power, all, heal). A skill with `cutin: true` shows its user across the screen first. A faction's `generals` march as a clash too, the strongest up to `clash.units`. `gozen sim campaign --tactic` compares the tactics. A script's `order` takes several generals with their tactics.
- `regions.<id>.landmark` (and `landmark_scale`): a cut-out picture of the region's city or fort stood on the campaign map's terrain at its point, with the owner's flag, smoking while `region.<id>.fought` is this turn or the last. `landmark_ground` (0 to 1, default 1) settles it onto the terrain with a foot shadow, a faded bottom edge and colours drawn toward the ground.
- `regions.<id>.area`: a region's shape on the campaign map, filled in its owner's colour with its border; `gozen check` reports areas that overlap or leave the picture.
- A campaign's map no longer draws every road and border by default: an area is only a faint wash of its owner's colour (none for a free region), and only the region chosen gets an outline and a thin arrow to each neighbour held by another side it can march on. `region_roads` and `region_borders` on the map (`selected`, the default, or `always`) bring back the lines of all the roads and the outline of every region; `draw_roads` is not read on a campaign's map.
- Five Banners (`examples/campaign`), the campaign sample: three factions, five regions and ten weeks, in English and Japanese, playable in the browser (`/play/campaign/`); `make campaign` and `make campaign-graphics` check it. The cookbook's "Make a campaign", the guide's "Campaigns" and the skill's campaign section describe the words.
- `gozen check` reports a faction or region written in an expression that is none (an owner compared with a misspelt faction, `next_to`), and events that call themselves on every run.
- A save made between commands keeps the random numbers (the envelope's `rand`), so `gozen.Restore` and the screen go on drawing the numbers the saved game would have.
- Dungeon themes (ADR 0032). `theme: cave` in a dungeon or in one of its `looks` fills the walls, door, floor and ceiling pictures and the floor and ceiling colors from `assets/dungeon/themes/cave/`; anything the YAML writes itself wins. `gozen theme list` names the five themes (`cave`, `ice`, `ruins`, `castle`, `crystal`) and `gozen theme add <name> <game-dir>` copies one into a game (it keeps files the game already has; `--force` replaces them). The pictures are embedded in the `gozen` command only, so game binaries do not carry them, and no network is used. `gozen check` fails with the new GZN1111 when a named theme is not in the game and says to run `gozen theme add`. The pictures are CC BY 4.0. The schema gains `Dungeon.theme` and `DungeonLook.theme`; the schema version does not change.
- The README and the site point GitHub Actions users to setup-gozen, which installs the release binary of the version in `go.mod`, with a CI section in `docs/development/ci.md`.

### Fixed
-- `gozen.Explore` no longer advances the random numbers of the session it is given when it picks its own seed, so a session saved before and after an exploration is the same.
 `chat.Mask` catches a word written in half-width kana or with a voiced mark as its own character (a half-width katakana followed by a half-width voiced mark, or a kana followed by U+3099). It now normalizes the text with NFKC before matching and hides the original characters of the match.
- The lines, choices and notices of a troop's events in a battle reach the trace (`say` and `notice` lines marked `in_battle`), so `gozen play trace` shows them, a replay compares them and `gozen play trace --check` checks them (GZN1404). Skip mode now stops before a battle line not read, as it does outside a battle. A replay of a trace written before this change, which has no battle lines, still matches.
- `gozen check` warns of an expression that uses a function's name as a value, such as `floor + 1` in a tile's commands where `floor` is the function and the floor's number is `var.floor` (GZN0114). Such an expression failed only when it was evaluated. `floor` stays the floor's number in `generate.size`, `generate.place`'s `count` and a roamer's `count`, `appear`, `wait` and `every`.
- A script's `walk` (and `face`) on a map or in a painted scene moves the party without a key, so the trace had no input for it and a replay of the trace stayed where it was and diverged. The trace now writes it as an `act` line (`walk`), and the replay walks the same way. A walk in a dungeon presses keys and was already in the trace.
- `DirStore` and `MemStore` refuse a save name that starts with a dot (`ErrInvalid`). `DirStore` wrote such a save but its `List` left it out as a hidden file, and it could take the name of a write's temporary file.
- `gozen check` checks `set: {actor.<id>.tactics: {...}}` written as a mapping: an unknown `mode`, a `preset` that `battle.tactic_presets` does not have (the member had no rows in battle) and `mode: preset` without `preset` are errors.
- A point of a map or a spot of a painted scene written without `at` (`fork: {}`) is the error "needs at", as one written empty (`fork:`) was; it loaded and stood at the corner of the picture.
- A key written beside a YAML merge (`<<: *base`) in `data/` or `game.yaml` overrides the merged one, as YAML means, wherever it is written. It was the error "duplicate key" when written after the merge and lost to the merge when written before it. A merge of a sequence of mappings is still not read.
- A line run from the F8 panel's Command tab (or a script's `do`) at the title, where no game runs, says so and is traced as a `dev_do` line with that error; it left an empty message and no trace line. A line whose YAML cannot be read is traced with its error too.
- The Edit and play loop page said F5 waits in a menu until the field is back; the field menu, the settings, the gallery and the character book are rebuilt at once and stay open, and only a battle or another screen makes the reload wait.

## v0.2.0 - 2026-10-21

Visual novels join RPGs: schema version 4 adds the novel window's roll back, skip, staging, voices and a second language, and `--dev` gains the F8 development panel. A game of schema version 3 or earlier needs no change.

### Added

- Schema version 4 for novel games (ADR 0025 to 0029). Its first word is `ui.rollback` in game.yaml (0 to 64 earlier events to roll back into, 8 by default; 0 turns rolling back off). The words of version 4 in a game of version 3 or earlier are the error `<word> needs schema_version: 4`; YAML of version 3 is read as is.
- Rolling back in novel games (ADR 0025): the "Back" button of the novel band, Q or the wheel up shows the line before with the state before it (flags, variables, items, answers), into up to `ui.rollback` earlier events; a battle, shop, save, screen or move stops it. The band also has "Save" and "Load". A script presses `back`, `save` and `load`; the trace writes `rollback` and `resume` lines, and `gozen play trace --check` fails with GZN1405 when a rollback did not go back.
- Skip mode and scene skip for novel games (ADR 0026). N or the new "Skip" button of the novel band passes the lines read until a line not read, a choice, a battle or the end of the events; Page Down or "Skip scene", shown when every line of the running event was read, goes at once to the next choice or line not read. An option taken before is drawn in the accent color. A script presses them with `press skip` and `press scene_skip`, a trace's `say` lines carry `read` and its `skip` lines what skipping did, `gozen play trace` marks the lines not read, and `gozen play trace --check` fails with GZN1404 when skipping passed one.
- Staging words for novel games (ADR 0028, schema version 4): `stand` places portraits on the novel window's stage as written (`who`, `face`, `at`, `enter: fade|slide`, `leave`, `none`); `effect` takes a map (`name`, `who`, `seconds`, `color`, `hold`) to shake one portrait or fade through a color, and plays the reactions of moving portraits (`nod`, `hop` and the rest); `music` takes `fade` and `stop`; `wait: {seconds, skip: false}` holds in skip mode; `sfx: {name, wait: true}` holds until the sound ends. The session's effects and the paths of `Explore` carry `stand`.
- Voices (ADR 0028, schema version 4): `say.voice` names a line's recording, in the speaker's `voices` folder or as a path under `assets/`; it plays when the line opens and stops at the next (`ui.voice.cut`), auto waits for it (`ui.voice.auto_wait`), and lines passed by skipping or a replay stay silent. The settings have a voice volume and one for each voiced actor. `gozen check` reports missing voices and warns of the lines of a voiced actor without one (GZN0109); a session and `Explore` see `Effect` kind `voice`; a trace has `voice` lines, and `gozen play trace --check` reports a voice played while skipping or one that could not be read (GZN1406).
- The game's text in two languages (ADR 0027, schema version 4): `written_in` is the language of `data/`, `languages` the languages the player may choose, and `lang/<code>.yaml` maps each text to its translation. Lines, speakers, choices, prompts and notices are translated as they are shown, the names of the definitions when the language is chosen; read lines stay read in every language. The settings have a language row; changing it shows the open line, its speaker, the question, its options and the backlog in the new language at once, with the values their `{expressions}` had. `gozen check` reports a translation that changes an `{expression}`, warns of stray keys (GZN0110) and of each text not translated (GZN0111), and lays out the lines in each language. A game loaded with an overlay that sets `language` gives its requests in that language.
- A choice can have an `id` (schema version 4): the state remembers the option taken, read as `chose.<id>`.
- A save made in the middle of an event goes on at its line: it holds the state when the event began, a cursor (the event, the line, the answers) and the random bytes, and the screen and `gozen.Restore` begin the event again and read on to the line.
- The development panel (ADR 0029): F8 under `--dev` opens tabs of the state (flip a flag, step a number), a table of the flags the events set and read, the events to jump to with their read rates, a line of YAML to run, and the frame meter; its tables are measured in the font, so the values line up whatever the length of a name. Edits go through `set` (trace `dev_set`), jumps start the event at a line (trace `jump`); a script does the same with `jump EVENT [LINE]` and `do YAML`, presses F8 as `press panel`, and runs a line typed into the Command tab (`type`) with `press ok`.
- `gozen check` warns of a flag set but never read (GZN0112) and read but never set (GZN0113); a flag declared in `state.names` is exempt. `gozen book` has a Flow section with a mermaid graph of the events.
- `DB.StateUses` in the schema package indexes where each flag, var, item and other name of the state is written and read (events, troops' events in battle, places), shared by the checks of flags, `gozen book`'s flow and the `--dev` panel.
- The novel sample, After the Pass (`examples/novel`, a module of its own like Go Zen): a short story at a tavern in the novel window, with two choices read as `chose`, a flag, `stand` and the other staging words, three endings with their own pictures, and a Japanese translation in `lang/ja.yaml`. Its pictures are CC BY 4.0. Its tests read every way through it and the Japanese text with `gozen.Explore`; `make novel` and `make novel-graphics` run them in CI. The README and the site's top page show novel games with pictures taken from it (rolling back, skipping to the line not read, the language, staging, an event picture), the site plays it in the browser at `/play/novel/` (checked by `make website-play-check`, which now also leaves out the frame meter's first numbers after the first frame when a stand-still posts them late), and `skills/gozen` has a section on novel games.
- The README and the site have a Playtesting section: a picture or GIF of each key of `--dev` with one line (F5 reload, F9 notes, F7 win rates, and the F8 panel's State, Flags, Scenes, Command and Frames tabs), taken by `make docs-images` like the others. A run of the picture ledger can play a copy of a sample's game and change one of its files after a shot (`edit`), which films the hot reload.
- The character book (ADR 0031, schema version 4): `profiles.<id>` in data/ gives a character a page with a name, a title, the standing picture and the faces to switch between (a puppet moves), fields of the game's own labels, an introduction with `{expressions}` and how the character sees the others. The Characters screen lists them (a shadow and ??? until `when` holds; once open, kept in `gallery.json`) and opens with `open: profiles`, from the title and the menu and the novel bar when `ui.profiles: true`, and under `--dev` from the title, the menu and F6, with every page open. A profile's icon, like the other face icons, is cut around the face `gozen art faces` found (assets/faces.json), which now also looks at the actors' and the profiles' standing pictures of a game with a character book; `gozen check` warns of one without a box. `gozen check` reports the actors, pictures and faces a profile points at and does not find, its expressions and its relations; a session reads `profile.<id>.unlocked`. `make docs-images ONLY=a.jpg` remakes one picture of the ledger.

### Changed

- The minimum Go version is raised from 1.26.9 to 1.26.10: govulncheck at 1.26.9 reaches GO-2026-6809 in crypto/x509, fixed in 1.26.10.
- schema_version 4 is opt-in. The words of version 4 in a game of version 3 or earlier are the error `<word> needs schema_version: 4`; a game that stays at version 3 needs no change to its YAML.
- Saves are written at format version 2 (the cursor of an event, the random bytes and the state's `chose`). A save of version 1 is still read and is written back at version 2 on the next save. An engine before this one refuses a save of version 2, so a game that updates should update its players' engine at the same time.
- A read line is known by its source, the speaker and the text as written before `{expressions}` and any translation, so a line with a variable is read once whatever the value (ADR 0026). `read.json` is now an envelope with a format version and the game id, like `gallery.json`; the bare list of earlier versions is read, its keys still count for one version, and it is kept as a backup on the next write. A record of another game or of a newer engine is left as it is.
- F8 under `--dev` opens the development panel instead of toggling the frame meter; the meter is the panel's Frames tab, which leaves the game running. `?fps` in a browser shows the meter as before.
- The settings show only the rows a game uses: a game without troops has no battle rows, one without voices no voice rows, one with a single language no language row.
- The README's and site's screens: the F7 and F8 pictures moved to Playtesting, and Go Zen's event picture gave way to the novel sample's ending picture with its line.
- Screenshots (a script's `shot`, `--shots`, `--until`, `gozen play shots`) are written off the game loop by background workers, as PNG at the fastest compression: a filmed run no longer waits about a second for each 1920x1080 frame (the Go Zen battle capture of 183 frames took 249 s and now takes 17 s). The pixels are the same; the files are about 15% larger. All of them are written before the game exits.
- `gozen check` loads the puppets of a game side by side.
- The dungeon view reuses its vertex buffers instead of allocating them for every wall and floor each frame: a 10-second walk in Go Zen's dungeon allocated 1.45 GB and ran 80 garbage collections, now 0.18 GB and 24.
- Loading a game decodes colors from their nodes and keeps the fields of each definition type, about a fifth faster with a fifth less memory (Go Zen 149 ms and 71 MB, now 118 ms and 55 MB).
- A save read again (each trial of the F7 measurement and of `gozen sim battle --state`, a rollback) skips the checks it already passed and only decodes the state; `gozen sim battle --state` takes about half the time.

## v0.1.0 - 2026-10-21

The first public release.

### Added

- `ui.talk_portrait` in game.yaml (schema version 3) places the speaker's picture beside the `box` message window (`x`, `bottom`, `height` as fractions of the screen), so a game can bring the speaker close; Go Zen shows the upper body. `title_text` (sizes, letter spacing, colors) and `fonts.subtitle` letter the title screen; Go Zen's title is set in Uncial Antiqua and Cinzel (SIL OFL 1.1) over the town map, and its inn opens the skill tree. A script's `play NAME EVERY` films a battle every EVERY ticks. The README's pictures of the plaza, the town map, the dungeon, a battle, a cut-in and a moving portrait are GIFs made by `make docs-images`, and its first GIF runs through the map, a dungeon, a battle and a talk; a GIF of the image ledger can join frames of several runs (`run:` in `frames`). The commands to verify a release moved from the README to the site's Install page.
- `skills/gozen`: an Agent Skill for Claude Code and Codex. It holds the minimal game, the required parts, the YAML traps, the error codes and `gozen sim`, and the rule to run `gozen check` until it passes. Its commands are run by the docs tests.
- Go Zen in the browser: `make website` builds the sample for `GOOS=js` into the site at `/play/go-zen/`; the program fetches the game's files before it starts, with the pictures as WebP of the same size (57 MB of files become 18 MB) and the page showing how much is left. ### Fixed

- The way a `walk` takes in a dungeon (in events, sessions and the headless player) now goes over a tile with `once` that has gone off, and, when there is no other way, over a tile that keeps the party where it is (a steam vent that hurts, a roamer to fight); it still never steps on one that may take the party elsewhere. A generated floor whose only corridor held such a tile left the goal unreachable.
- check: a line said by an actor with a moving portrait (`puppet`) is checked against the portrait's faces, not against pictures in the `faces` directory, so the faces only the portrait has are no longer reported as missing.
- A `walk` command longer than 64 steps no longer stops with "events nested too deep": each step goes on as the walk's continuation instead of a frame nested in the last one.
- Moving from a generated floor with roamers to another dungeon with `move` leaves the roamers behind; walking there used the last floor's roamers and could panic.
- react: `Config.MaxRunes` also cuts the text that a game's own `Analyzer` receives. A `React` call whose condition fails to evaluate no longer records the text as recent, so a retry is not counted as a repeat; the turn still advances and expired memories are dropped, as the documentation now says.
- chat: `Log` copies `Message.Values` when a message is posted and when `Post`, `Recent` and `Since` return it, so changing a returned map no longer rewrites the log. A crowd script with a NaN `rate` is rejected.
- A YAML value with a tag where a list is expected (for example `names: !x 0`) made the YAML library panic. Crowd scripts, reaction books, puppet specs, game data and the command's configuration files now report it as an error. A fuzz test for `chat.Parse` and `react.Parse` keeps such inputs.
- battle: state multipliers on a stat and state resistances are multiplied in a fixed order, so the same seed rounds the same way on every run. A party member's weapon element is taken in the game's slot order. `rpg.Actor.StateResist` follows the same order.
- `rand(n)` and `rand(a, b)` in expressions return an error for NaN and cap counts above 2^53 instead of panicking. Event gold, damage and experience amounts that are NaN or out of range saturate instead of wrapping.
- The expression parser rejects nesting deeper than about a hundred levels with an error instead of risking a stack overflow.
- assetfs: `OverlayFS.Stale` returns the error when an original picture cannot be read (permission, I/O) instead of silently leaving it out; only a missing original is skipped. The development hot reload likewise treats only missing files as absent.
