# Changelog

Changes before the first public release are tracked under Unreleased. All packages and the gozen command share one module version. The v0 API is being established; experimental packages, when there are any, live under `x/` and carry no compatibility promise.

## Unreleased

### Added

- `skills/gozen`: an Agent Skill for Claude Code and Codex. It holds the minimal game, the required parts, the YAML traps, the error codes and `gozen sim`, and the rule to run `gozen check` until it passes. Its commands are run by the docs tests.
- Go Zen in the browser: `make website` builds the sample for `GOOS=js` into the site at `/play/go-zen/`; the program fetches the game's files before it starts.
- YAML game loading and validation, expressions, events, battle rules, world navigation and versioned saves.
- Headless execution, Ebitengine presentation, audio and an embedded-game runner.
- The gozen command with six tools: check, sim (battle, dive, floors, design), play (trace, notes, shots), book, pack (release, trial) and art (prompt, mosaic, fetch, faces, puppet), plus version and help; ONNX inference in art mosaic and art faces needs a cgo build and uses user-supplied models and runtime libraries.
- Diagnostic codes (ADR 0024): a diagnostic can end with a code such as `[GZN1101]` whose first digit is the exit status, `gozen check --format json` and `gozen.Diagnostic` carry it as `code`, `gozen help GZN1101` explains it, and the site lists them on the Error codes page. An old command name exits 2 and names the new one (`gozen curve` is `gozen sim dive`); `check --no-layout` is `check --only structure` and `layout` is `check --only layout`. A troop or location named on the command line that the game does not have exits 2.
- Original minimal, headless and graphical examples with asset source and license records. The Go Zen sample (`examples/go-zen`, a module of its own) has CC BY 4.0 pictures and music; the code is MIT.
- Architecture dependency checks, public API inventory checks and CLI contract tests using atago.
- CI for lint (golangci-lint with gofumpt, go mod tidy, actionlint and zizmor for the workflows), unit tests across three operating systems and minimum/stable Go versions, graphics, CLI contracts, native and cross-builds, examples, race detection, govulncheck and CodeQL.
- A development balance panel (F7 with `--dev`): win rate, HP left after a win and win rate by level for the battles at the current location, measured inside the game loop with the same functions and seeds as `gozen sim battle`, and measured again after a hot reload. `gozen sim battle` gains `--state` (start from a saved state such as an F9 note's `.save`), `--as-is` (keep its HP, MP and states), `--hp` and `--streak`. When the party is hurt the panel puts the current-HP win rate under the healed one and shows how many wins in a row the current HP lasts.
- GNU-style options for the gozen command, its prompt and mosaic subcommands and the game runner: `--name value` and `--name=value`, one-letter forms for common options (`-n`, `-o`, `-v`, `-h`), options before or after arguments, and `--` to end them. Single-dash long options such as `-seed` are rejected. Every `--help` has the same shape: a title line with the version, [Usage], [Examples], grouped [Options], notes with the requirements, and the project links.
- The engine's own words (menus, battle messages, settings, saves, gallery, development panels) come in English and Japanese. `language: en` (the default) or `language: ja` in game.yaml picks them, and `text` lays the game's own wording on top. A test keeps the English list in step with every key the code shows. `text.Use` now takes the language (`text.English`, `text.Japanese`). `gozen book`, `design`, `memos`, `shots` and `trace` write their documents in the game's language; gozen's own diagnostics are English. `gozen check` warns when `language` is unset but the game is written in Japanese, and when the regular font lacks letters of the chosen words.
- Moving portraits (`puppet`): one picture plus small difference pictures (closed eyes, mouth shapes, other faces) in YAML blink, move the mouth while speaking (`Speak`/`Stop`), breathe, sway and tilt the head, let the hair trail behind on a spring, play one-shot reactions (`React`: hop, shrink, shake, nod, tilt) and fade between faces (`SetFace`). The head and hair move by deforming a mesh, so no layered artwork or rig is needed. Full-size difference pictures are cut down to the part that differs when loading. `gozen art puppet` checks a puppet, prints where each overlay lies, and with `--out` writes the small pictures. `examples/puppet` shows a streamer whose motions are tried with keys; its pictures are CC BY 4.0.
- puppet: swaying parts (`springs:` in the YAML) for ribbons, hems, sleeves, cords and the like. Each part is a rectangle or polygon with a root (an edge or a point), what it follows (`head`, or `body` for breathing and hop, shrink and shake), an axis, a spring and a cap; the far end trails the most and later parts lie over earlier ones. The hair is the first such part and moves exactly as before. No new Go API; `motion.hair` stiffness and damping are now capped at 10000 and 1000, and a stiff spring or a low TPS is stepped in smaller parts so it stays stable. `examples/puppet` sways the hoodie's drawstrings.
- The README and website pictures come from a manifest (docs/images/manifest.yaml) that says which sample, script and shot makes each one; `make docs-images` remakes them under Xvfb and CI fails on a stale picture. The shell steps and YAML examples of the README and the site are run and loaded in CI (`make docs-steps`), and the built site is checked for broken links (`make website-check`). The getting-started steps now run `go mod tidy` before copying Go's font, and the mosaic example marks the image for hand-drawn regions before adding one.
- The documentation is English only. The Schema page of the site describes every type and field (generated from data/schema/types.schema.json, with a description for each in website/data/schema_fields; a field without one fails the build and the tests), and docs/schema.md is gone. A cookbook page gives 30 short recipes for common tasks, each loaded by the tests; its commands are collected in one section. Tests now fail on Japanese in a Markdown document, on adult vocabulary outside the mosaic tool, and on a broken link or heading between the repository's documents.
- Contribution and security reporting guidance, plus Dependabot updates for Go modules and GitHub Actions.
- A release pipeline for the gozen command (not yet run): archives for Linux, macOS and Windows on amd64 and arm64, `.deb`, `.rpm` and `.apk` packages, and a Homebrew cask. Release archives and Linux packages include the license texts of the linked dependencies under THIRD_PARTY_LICENSES/, an SBOM per archive, a cosign-signed checksums.txt and SLSA provenance. The prebuilt binaries have no ONNX inference. `gozen version` prints the release version.
- Nightly fuzzing, per-platform dependency license checks, gitleaks, OpenSSF Scorecard and himorime benchmarks in CI; a code of conduct, issue and pull request templates and a contributors section.

- Schema version 3 (ADR 0022): maps and painted scenes as two more ways to show a location, beside the menu and the dungeon. `map:` is one picture with `points` (each may lead `to` a location, say a `locked` line while its `when` fails, run `do` once) joined by `roads` (`via` bends, `steps`, `encounters` met on the way, `do`); `stage:` is the location's background painted from a fixed camera with its `depth`, `scale`, `walk` and `blocks` polygons, `fronts` that hide those behind them, named `spots`, areas for its `exits`, places for its `people` (standing `at` or walking a `path`, drawn as a box `doll`) and `things` to look at. The rules know one position, `spot` (a point or a spot, saved, readable as an expression and settable with `set` in the development mode); the free walk between points is the screen's and is not saved. The points of a map and the people, things and spots of a stage are ordinary menu entries, so `pick`, `Explore` and `gozen sim design` walk them unchanged; `exits[].at` and `move.at` name the spot or point to arrive at. `Person.bubbles` are lines said now and then in a balloon, `Actor.doll` dresses the leader's doll. `gozen check` reports their mistakes with file and line and warns of points and exits no one can reach; `gozen book` lists them. No public Go API is added. The game window shows a stage as the painting with the leader walking it as a box doll (arrow keys; a click walks to the floor; walking into an exit's area leaves; the menu key lists the entries and walks to the one chosen), hidden behind the fronts and where the depth is nearer than the feet; scripts walk to a spot with `walk SPOT`. The people stand or walk their paths as dolls colored from their pictures, say their `bubbles` now and then (in balloons just over the head, all of one size set by `ui.balloon` in game.yaml, kept on the screen and apart, with a round face from the doll's own `icon` picture, or cut around the face that the new `gozen art faces` finds with the face detector of `gozen art mosaic` and writes to `assets/faces.json`; the game reads that file and runs no model), turn to the leader to talk (OK within reach of what the leader faces), and things and spots with do run when looked at or stepped on. A map shows its picture (with the roads painted in it; `draw_roads` draws their lines too) with a small marker on each point (a pin, or the map's or the point's `marker` picture) and a name plate kept clear of the others (its text sized by `label_size`; the unvisited as `unknown` says: hidden until the roads reach them, dim, a "?" plate, or named; the closed gray), and the token (the map's picture, else the leader's round face as in the balloons, sliding with a ring at its feet; `token: doll` walks the leader's doll instead) goes along the roads to the point chosen with the arrow keys, a click or the menu's list; a road's battles and do come when the token reaches its end. A click or a tap in a painted scene walks the way around what blocks (A*), and on someone or something walks there and talks or looks; a touch is a click where it lifts, a long press on a map or a scene opens the list (elsewhere it is nothing, and lifting still clicks), two fingers are the right click; scenes and maps run in a browser (GOOS=js).

### Changed

- The sample game is Go Zen (`examples/go-zen`): a town on a painted map, a plaza to walk, a three-floor dungeon, moving portraits and a soundtrack, at 1920x1080. Wayfinder (`examples/play`) was removed; the README and site pictures are taken from Go Zen.
- The minimum Go version is raised from 1.26.4 to 1.26.9: govulncheck at 1.26.4 reaches standard-library advisories in net/http, os, encoding/xml and encoding/asn1 that 1.26.9 fixes.
- Schema version 2 (ADR 0021): the commands `pick` (a menu entry of the current place), `turn`, `step` and `walk` (dungeons), `use` (an item from the menu, with `target`) and `equip`; `set` on `gold`, `item.ID`, `party`, `location` and `actor.ID.tactics` (the last three take names as written: `location: camp`, `party: [hero, sela]`), and on `actor.ID.hp`, `mp`, `exp`, `level` and `sp` only in the development mode and tests (`gozen check` warns where game data does it); the expression names `menu`, `map`, `cell(x, y)`, `result`, `over`, `cleared`, `repairs` and `actor.ID.tactics`; and `verbs` and `screens` in game.yaml to declare a game's own commands and screens. Versions 0 and 1 read as before; the new words need `schema_version: 2`. The examples use version 2.
- An unknown command name is still an error unless game.yaml declares it in `verbs`, now with the nearest command (`did you mean "say"?`). `gozen check --format json` prints every error and warning as a JSON array of `{file, line, col, path, message, severity}`. `data.Load` returns definition errors as `data.Diagnostics` with the same fields.
- The root package `gozen`: `Load` and `Validate` a game, `New` or `Restore` a `Session`, `Do` YAML commands on it (one at a time, each followed by what it sets off), drive it from a screen with `Start`, `Next` and `Answer`, read it with `Query` (an expression into a Go value), `Save` and `Clone` it, try every branch with `Explore`; `Request` and `Effect` are single structs, a `Policy` answers choices and battles, and `DirStore` and `MemStore` keep saves. The older packages stay until the users have moved.
- `play.Main` runs a game in a window with the standard options (what `runner.Run` did; `runner.Run` now calls it and goes away later). `play.New` takes a `gozen.Session` and returns a `Screen` (an `ebiten.Game`) for a program's own loop or a browser; `play.Config` is `Store`, `Mute` and `Output`. Saves go through a `gozen.Store`: the user's config directory by default, localStorage in a browser (GOOS=js), memory for scripted runs. Wayfinder runs in a browser.
- Breaking: `play.New(fsys, Config)`, `play.Game` and `play.Development` are gone; use `play.Main` with the options, or `play.New` with a session.
- Breaking (ADR 0021, stage 6): the rule packages are no longer public. `rpg`, `event`, `battle`, `headless`, `expr`, `savefile`, `text`, `world` and `dungeon` moved under `internal/`, and `runner` is gone; use the root package `gozen` (`Load`, `Session.Do`, `Session.Query`, `Explore`) and `play.Main`. `data` is now `schema`, the YAML definitions as Go types, counted in `api/schema.txt`. `react.Book` and `chat.Script` are opaque (read their parts with `YAML`); `react.Mind.NewSession` is `Reset`. The public API went from 1,450 identifiers to 197, plus 619 in the schema.
- More words for tests and tools (ADR 0021): the commands `buy` and `sell` (a shop's trade, as its screen does it) and `act` (a move for the next battle fought on AUTO), and `equip` with only `actor` for the best equipment; `set` on `pos.x`, `pos.y`, `pos.facing`, `steps` and `roamers: none` in the development mode, and `actor.ID.tactics` with its rows; the expression names `ran.EVENT` (`count`, `order`), `cell(x, y).raw` and `.shown`, `completed` and `moved`, and `actor.ID.tactics.rows`. `Load` takes extra file systems laid over the game, `DefaultPolicy.Prefer` picks options by label, `ExploreOptions.NoArrive` skips arrivals, `Effect.Faces` and `Effect.At` keep an image's portraits and its place among a path's requests, and a say request's `ID` is the speaker's actor.
- Breaking: the public API is being cut down to a small shape (ADR 0021, read with an expression and change with a command). First step: `assetfs` and `sound` are no longer public; `data` no longer aliases the definition types that no caller names (43 types), and `data.Validate`, `data.CurrentSchemaVersion` and `play.Run` are gone; helpers used only inside their own package (in `battle`, `chat`, `event`, `expr`, `headless`, `react` and `rpg`) are unexported; the inventory no longer lists members of unexported types; the empty `x/` placeholders are removed.
- Breaking: a game without `language` now shows the engine's words in English. Japanese games add `language: ja` to game.yaml. Wayfinder sets `language: en` and keeps only its own wording in `text`.

### Fixed

- The way a `walk` takes in a dungeon (in events, sessions and the headless player) now goes over a tile with `once` that has gone off, and, when there is no other way, over a tile that keeps the party where it is (a steam vent that hurts, a roamer to fight); it still never steps on one that may take the party elsewhere. A generated floor whose only corridor held such a tile left the goal unreachable.
- check: a line said by an actor with a moving portrait (`puppet`) is checked against the portrait's faces, not against pictures in the `faces` directory, so the faces only the portrait has are no longer reported as missing.
- A `walk` command longer than 64 steps no longer stops with "events nested too deep": each step goes on as the walk's continuation instead of a frame nested in the last one.
- Moving from a generated floor with roamers to another dungeon with `move` leaves the roamers behind; walking there used the last floor's roamers and could panic.
- react: `Config.MaxRunes` also cuts the text that a game's own `Analyzer` receives. A `React` call whose condition fails to evaluate no longer records the text as recent, so a retry is not counted as a repeat; the turn still advances and expired memories are dropped, as the documentation now says.
- chat: `Log` copies `Message.Values` when a message is posted and when `Post`, `Recent` and `Since` return it, so changing a returned map no longer rewrites the log. A crowd script with a NaN `rate` is rejected.
- A YAML value with a tag where a list is expected (for example `names: !x 0`) made the YAML library panic. Crowd scripts, reaction books, puppet specs, game data and the command's configuration files now report it as an error. A fuzz test for `chat.Parse` and `react.Parse` keeps such inputs.
- battle: state multipliers on a stat and state resistances are multiplied in a fixed order, so the same seed rounds the same way on every run. A party member's weapon element is taken in the game's slot order. `rpg.Actor.StateResist` follows the same order.
- `rand(n)` and `rand(a, b)` in expressions return an error for NaN and cap counts above 2^53 instead of panicking. Event gold, damage and experience amounts that are NaN or out of range saturate instead of wrapping.
- The expression parser rejects nesting deeper than about a hundred levels with an error instead of risking a stack overflow.
- assetfs: `OverlayFS.Stale` returns the error when an original picture cannot be read (permission, I/O) instead of silently leaving it out; only a missing original is skipped. The development hot reload likewise treats only missing files as absent.

### Verification limits

- Published installation, Windows/macOS runtime checks and remote CI results remain unverified locally. Cross-builds do not establish runtime support.
- Real audio and ONNX inference need separate runtime verification; model-dependent test skips are not inference results.
